[pfpl][pfpl]

    `abstract syntax` defines syntactic categories and term constructors
    `judgment` denotes a formal claim about syntax or behavior

    `derivation` records an application tree of inference rules
    `statics` defines compile-time validity judgments
    `dynamics` defines execution judgments

[open logic][open-logic]

    `term` is generated by the formation rules of a signature
    `formula` is generated by logical formation rules
    `formal system` combines expressions, axioms, and inference rules
    `deductive system` defines derivability by inference rules
    `proof calculus` is a deductive system for constructing proofs
    `axiom system` presents a class of structures by sentences
    `theory` is commonly closed under logical consequence
    `theory presentation` supplies a signature and generating axioms
    `structure` interprets the symbols of a signature
    `satisfaction` relates a structure to a sentence
    `model-theoretic specification` denotes its permitted structures by satisfaction

[core calculus][core-calculus]

    typing rules define valid core terms
    reduction rules define core computation
    surface conveniences can be translated into the core calculus

[lean core][lean-core]

[rocq core][rocq-core]

    inductive declarations add constructors and eliminators
    surface commands elaborate into kernel objects

    typing and definitional equality govern framework objects

[institution][institution]

    sentences vary covariantly with signatures
    models vary contravariantly with signatures
    satisfaction is indexed by signature
    satisfaction is invariant under change of notation

[casl][casl]

    `equational specification` defines data by equations over terms
    `abstract data type` hides representation behind named operations and laws

    subsorts define inclusion relations between sorts
    operations name constructors and functions
    predicates name relations
    equations state laws over terms
    conditional axioms restrict when laws apply
    a model interprets every declared symbol
    a specification denotes the class of models that satisfy its axioms
    an initial model can select the freely generated interpretation

[maude][maude]

    equations identify equivalent state representations
    rewrite rules define possible state transitions
    rewriting modulo equations defines concurrent computation
    the generated transition relation defines reachable states

[term rewriting][term-rewriting]

    normal forms have no outgoing reduction
    `term-rewriting system` adds a ranked signature, variables, and terms
    rewrite rules have a left term and a right term
    substitution instantiates rewrite variables
    term contexts permit rewriting below the root
    confluence and termination are properties of rewrite relations

[redex][redex]

    judgment forms define relations by inference rules

    evaluation contexts select reducible positions
    test forms check semantic claims
    [redex relations][redex-relations]

[k framework][k-framework]

[plotkin sos][plotkin-sos]

    labels represent observable actions

    one-step rules generate a labeled transition system
    `labeled transition system` consists of states, labels, and labeled transitions

[redex semantics][redex]

    `big-step semantics` relates an input configuration directly to a result
    `natural semantics` is another name for rule-based big-step semantics
    small-step derivations expose intermediate configurations
    big-step derivations omit intermediate configurations

[tla][tla]
